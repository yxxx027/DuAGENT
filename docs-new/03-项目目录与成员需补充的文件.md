## 三、各成员需补充完善的内容

### 3.1 成员 1 需完善的文件

#### `agents/structured_parser.py`

当前状态：`parse()` 和 `reassemble()` 有基础实现，但需要完善。

| 方法 | 当前状态 | 需补充内容 |
|------|---------|-----------|
| `parse()` | 基础 JSON 提取 + fallback | 优化 JSON 解析鲁棒性，处理 LLM 返回格式不规范的情况 |
| `reassemble()` | 简单拼接 | 优化重组策略，使重组后的 Prompt 更自然、更利于图像生成 |
| `_fallback_parse()` | 最小实现 | 增强容错能力 |

**具体改进方向**：
- 增加 `parse_batch()` 方法，批量解析多条 Prompt
- 优化 `reassemble()` 的重组逻辑，加入空间关系描述增强
- 增加 `_validate_structured()` 方法，验证解析结果完整性
- 处理边界情况：无空间关系、单物体、超长 Prompt 等

#### `prompts/structured_parse.txt`

当前状态：基础模板，有示例。

**需补充内容**：
- 增加 few-shot 示例（2-3 个不同类型的 Prompt 解析示例）
- 优化指令措辞，提高 LLM 输出 JSON 的合规率
- 增加对数量词、风格词、氛围词的处理规则

### 3.2 成员 2 需完善的文件

| 方法 | 当前状态 | 需补充内容 |
|------|---------|-----------|

| `generate_attribute_negations()` | 基础属性否定 | 增加更多属性类型的否定规则 |

## 四、文件依赖关系

```
run_structured.py
  ├── agents/structured_parser.py ← prompts/structured_parse.txt
  ├── agents/negative_prompt_generator.py ← agents/negative_rules.json
  ├── evaluation/clip_scorer.py ← (CLIP model, auto-download)
  ├── evaluation/visualize_results.py ← matplotlib
  └── utils_all/api.py ← openai
```

**开发顺序建议**：
1. 成员 2：`negative_rules.json` → `negative_prompt_generator.py`（无外部依赖）
2. 成员 1：`structured_parse.txt` → `structured_parser.py`（依赖 api.py）
3. 成员 3：`test_prompts.txt` → `clip_scorer.py` → `visualize_results.py`
4. 成员 0：`run_structured.py` → `run_structured.sh`（依赖所有模块）
